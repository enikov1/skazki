# Визуальная проверка сайта

## Почему локальный адрес не открывается из браузера Codex

`npm run dev` запускает BrowserSync на `http://localhost:3000/demo/` на машине разработчика. Облачный браузер Codex работает в отдельной среде и не имеет маршрута к `localhost` компьютера разработчика. Попытка открыть этот адрес из облачного Chrome завершается `ERR_CONNECTION_REFUSED`.

## Рабочий способ проверять страницы приложения

1. Развернуть текущую ветку на отдельном HTTPS staging/preview-домене. Preview должен исполнять Laravel, а не только отдавать статичные Pug-макеты.
2. Ограничить доступ staging паролем или корпоративным Access-шлюзом. Не открывать административную панель всему интернету.
3. Создать отдельную базу с синтетическими записями через `DemoContentSeeder`. Не копировать пользовательские данные production; включить `APP_DEBUG=false`, тестовый почтовый транспорт и отключить реальные OAuth-действия.
4. Создать отдельные тестовые учётные записи для гостевого, пользовательского, редакторского, модераторского и административного сценариев. Не использовать production-пароли и токены.
5. Передать URL preview. Для закрытых страниц вход выполняется через безопасный handoff браузера; пароли, коды и секреты не присылать в сообщения и не коммитить в Git.
6. Проверить основные маршруты в облачном Chrome: внешний вид, хлебные крошки, переходы и действия, формы и ошибки, горизонтальное переполнение, мобильную и настольную ширину. Сохранять снимки после каждого исправления.

## Что можно проверять без staging

- `npm run build` проверяет компиляцию исходной Pug/SCSS-демо-вёрстки.
- `npm run dev` показывает статический макет разработчику на своей машине.
- PHPUnit feature-тесты проверяют серверные ответы, права, формы, AJAX и тестовые данные.

Эти проверки не заменяют визуальный осмотр Laravel-страниц в браузере. Когда появится доступный staging URL, сначала проверяются главная, каталоги сказок/статей/аудио/раскрасок/игр, карточки материалов, профиль и ролевые страницы админки. Для сравнения мобильного и настольного вида дополнительно запускать браузерный прогон с viewport 375, 768 и 1440 px и сохранять снимки в CI-артефакт.
