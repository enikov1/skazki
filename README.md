# СказкоМир

Семейная библиотека сказок и занятий. Репозиторий содержит Laravel-приложение с серверными страницами каталога, аккаунтами, ролевой моделью и началом административного управления контентом. Исходники прежней вёрстки находятся в `src/` (Pug, SCSS, JS); сборка Gulp публикует их для просмотра на `/demo/`, закрытом от индексации.

## Что уже работает в основе приложения

- Серверный каталог опубликованных сказок с поиском, фильтрами по жанру и возрасту и пагинацией.
- Отдельные страницы сказок, метаданные, canonical, Book JSON-LD, похожие истории и HTML5 аудиоплеер.
- Регистрация, вход и выход по email/паролю; хеширование пароля, защита CSRF, ограничение частоты попыток входа, регенерация сессии.
- OAuth-вход Яндекс/VK после добавления ключей приложений в `.env`. Связь OAuth-учётной записи с занятым email автоматически не выполняется.
- Группы пользователей: пользователь, редактор, модератор, администратор; разрешения хранятся отдельно и назначаются ролям.
- Закрытая панель: обзор, создание и изменение сказок, назначение/публикация статуса, очередь модерации комментариев, управление ролями.
- Каталог статей для родителей с фильтрами и пагинацией, отдельная SEO-страница статьи, обсуждение с модерацией и лайками/дизлайками, редактор статей в панели.
- Личный кабинет: изменение имени, безопасная смена пароля и история открытых сказок.
- Защита от удаления последнего администратора и от самостоятельного снятия админ-роли.
- CI workflow с Gulp-сборкой и feature-тестами на SQLite.

## Запуск для разработки

Требуются PHP 8.3+, Composer, расширения PHP для выбранной БД, Node.js 22+ и PostgreSQL или MySQL. На Windows подойдёт WSL2 или локальная сборка PHP/Composer.

```bash
cp .env.example .env
composer install
php artisan key:generate
# Создайте PostgreSQL/MySQL БД и задайте DB_* в .env
php artisan migrate --seed
# Скомпилируйте макеты Gulp/Pug/SCSS в /demo
npm ci && npm run build
php artisan serve
```

Откройте `http://127.0.0.1:8000`. Дизайн-макеты можно посмотреть через ссылку «Все разделы» или напрямую `/demo/`. Это прототип для сверки вёрстки, не рабочий каталог с живым содержимым. Для разработки интерфейса удобно запустить `npm run dev`: BrowserSync показывает `/demo/` на порту 3000 и обновляет его при изменении Pug/SCSS/JS.

Чтобы создать первого администратора, временно заполните `ADMIN_NAME`, `ADMIN_EMAIL`, `ADMIN_PASSWORD` в `.env`, затем выполните `php artisan db:seed`. Используйте отдельный уникальный пароль. После выдачи роли удалите эти значения из runtime secrets. Не коммитьте `.env`.

Для OAuth создайте приложения в кабинетах разработчиков Яндекса и VK, задайте client ID/secret и callback-URL вида `https://ваш-домен/oauth/yandex/callback` и `https://ваш-домен/oauth/vkontakte/callback`. Если провайдер не возвращает email, учётную запись следует связывать с подтверждённым email отдельным сценарием.

## Перед production

Этот репозиторий — фундамент и первый рабочий вертикальный срез, а не заявление о готовом интернет-магазине/социальной сети. Перед публичным запуском нужно развернуть и проверить приложение на выбранной инфраструктуре, настроить TLS/домен, SMTP и проверку email, Redis, S3/CDN, резервные копии, мониторинг и восстановление, OAuth credentials и пользовательское соглашение. Контентная модель пока охватывает сказки и комментарии; публикации для родителей, раскраски, работы детей, реакции, история чтения, викторины, журнал аудита и продвинутые редакторские процессы требуют следующих миграций и экранов. Загружать реальные аудио/изображения через админку безопасным медиапроцессом тоже предстоит отдельно.

См. [архитектуру Laravel и план запуска](skazkomir-laravel-architecture.md) и [дорожную карту задач](ROADMAP.md).
